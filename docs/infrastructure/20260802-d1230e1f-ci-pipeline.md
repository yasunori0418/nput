# INF-d1230e1f: CI パイプライン（flake check の os×system マトリクスと E2E ジョブ）

## 構成

GitHub Actions 上の `test.yml`。テスト層の分離（lib = nix-unit / namaka、engine = Go ユニット +
tmpdir 統合、E2E = 非 NixOS + nix コンテナ）に対応して、**`nix flake check` に集約した層**と
**E2E** を別ジョブに置く。

| ジョブ | 内容 | 実行環境 |
|---|---|---|
| `flake-check` | `nix flake check -L`（lib のテストと engine の Go check を集約） | os×system の 3 環境マトリクス |
| `e2e` | 非 NixOS 環境 + nix コンテナでの E2E | 単一環境 |

マトリクスは `ubuntu-latest`=x86_64-linux / `ubuntu-24.04-arm`=aarch64-linux /
`macos-latest`=aarch64-darwin の 3 環境。x86_64-darwin は GitHub ホストの標準ランナーが
乏しいため CI 対象外で、`perSystem` の 4 system 定義は残したまま検証対象を 3 環境に絞る。

Go の check（go-vet / golangci-lint）は `CGO_ENABLED=0` のピュア Go で実行する。nput は
cgo 未使用のため、サンドボックスに C コンパイラを持ち込まずに検査できる。

nix のセットアップは composite action `.github/actions/setup-nix`
（`cachix/install-nix-action` + `cachix/cachix-action`・各 action は SHA pin）に閉じ、
`nix develop '.?dir=dev#ci' -c <cmd>` の CI 用 devShell からコマンドを叩く。

## トリガと変更検出

`pull_request` + `workflow_dispatch`。`push`（branches-ignore: main）は採らない — PR 経由運用
（main へ直 push しない）が前提で、push トリガは PR チェックと重複するため。

docs のみの変更で 3 環境マトリクスを回すのは無駄だが、**トリガ段の `paths` フィルタは使わない**。
required status check（→ INF-8b97573f）は生成されない check を `Expected` のままブロックするため、
`paths` で workflow ごと弾くと docs-only PR がマージ不能になる。代わりに専用の変更検出 composite
action を `needs` し、各ジョブを `if:` でスキップする（skip → "Skipped" = 成功扱い）。
「docs-only で nix を実走させない」意図は保ったまま、実現手段だけを移してある。
