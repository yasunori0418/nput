# REQ-496b1a07-5b74-416b-9e5f-3952b4c03737: entrypoint は nput.<name> に named manifest を公開し CLI は形ごとの attr path で build する

## 仕様

entrypoint は `nput.<name>` に named manifest（`mkManifest` の結果）を公開する。
1 プロジェクトに複数 config を置ける（役割ごと独立 profile・→ concept.md）。

| entrypoint | 公開形 | CLI が叩く build |
|---|---|---|
| `flake.nix`（直書き）| `outputs.nput.<system>.<name> = mkManifest { ... }` | `nix build <ep>#nput.<system>.<name>`（CLI が現行 `<system>` を差し込む）|
| `flake.nix`（flake-parts）| `perSystem.nput.<name> = mkManifest { inherit pkgs; ... }`（flakeModule 経由）| `nix build <ep>#nput.<system>.<name>`（同上）|
| `default.nix` / `shell.nix`（passthru・canonical）| `pkgs.mkShell { ...; passthru.nput.<name> = mkManifest { ... }; }` | `nix build -f <ep> nput.<name>` |
| `default.nix` / `shell.nix`（トップレベル attrset）| `{ nput.<name> = mkManifest { ... }; }` | `nix build -f <ep> nput.<name>` |

legacy entrypoint には flake の `<system>` に相当する次元が無く、addressing は
フラットな `nput.<name>` になる。

> **上の表は原文の写しで、規範は frontmatter が正**。表が併記する次の点は本 item の
> 規範ではない。
>
> - flake-parts 経路が満たすべき条件（transpose・`pkgs` の一貫性）→ REQ-c50df875-2cb0-4e72-8a21-858359a11cae
> - passthru 形を canonical とする理由と `mkShell` との共存条件 → REQ-c890ce4a-6528-4ab3-ac86-23d7aebff7da

## 出典

`docs/spec.md`「CLI 仕様」→「アドレッシング（`nput.<name>`）」の本文と表。

決定の実体は ADR-0007 §4「アドレッシング = 専用 `nput` 名前空間・named config」で、
legacy entrypoint の addressing を `nix build -f <ep> nput.<name>` に統一したのは
ADR-0032（ADR-0007 §4 の `nix-build -A` 記述を改訂）。
