# TC-cf8189c4: engine 結果から item と change への写像がインベントリ全数と実差分に一致する

## 条件

engine の実行結果を JSON ペイロードへ写す規則が、実際に起きたことと一致することを確かめる。
形ではなく内容を見る条件であり、適合チェッカの外側にある。

確かめる規則は次のとおり。

- **item はインベントリの全数** — 新しい manifest の entry と、前世代から stale 除去された
  旧 entry の双方が item として現れる。片方だけになると、消費側から見て存在したはずのものが
  消える
- **change は差分のある遷移だけ** — 状態が変わらない再 link は change を作らない。逆に
  dryrun の計画では、実際には差分があるので抑制しない。配置方式の変更（symlink から copy）は
  1 つの item と 1 つの変更へ束ね、二重に数えない
- **到達状態の 3 分割** — 完了した対象は成功、失敗した対象は失敗として原因の分類を持ち、
  失敗によって着手されなかった対象は skip として区別される。成功と skip を混ぜない
- **世代番号の前後** — 変更系は変更前と変更後の世代を持ち、初回は変更前を持たない。失敗して
  世代が動かなかった実行では前後が同値として観測される
- **読み取り系の情報** — 世代一覧は番号・日付・現行フラグを持つ行として `info` に載り、
  同じ世代番号を別のスロットへ二重に載せない。列挙結果に個別の item id は振らない

実 engine を通した経路でも同じ写像が成立することを確かめる（写像の入力を手で組むだけでは、
engine の返す結果の形との食い違いが残るため）。
