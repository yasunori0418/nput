# CASE-1fc8b8b9: e2e 01-project — project mode の配置と --all の部分失敗を実 nix で通す

## 対象

`tests/e2e/scenarios/01-project.sh`（ハーネスは `tests/e2e/run.sh` / `tests/e2e/lib.sh`）

## 検証内容

一時的な git リポジトリと複数の config を持つ fixture flake を作り、実 nix で一気通貫に
駆動する。ハーネスの中で最大のシナリオで、配置系と出力契約系の双方を覆う。

- **配置と冪等性** — git の toplevel 直下の配置先へ store の配置物が張られること、再実行で
  変化しないこと
- **item id の契約適合** — 出力の item id を niface の配布する id ベクタと突き合わせること
- **conflict の扱い** — 配置先を実ファイルで塞いだ状態の計画が conflict の終了コードで
  止まること、実行時の conflict は一般エラーの終了コードになること
- **エラー層の分離** — 対象に閉じた失敗が当該 item に載り、subject にもトップレベルにも
  重複しないこと
- **`--all` の部分失敗** — 1 つの config が失敗しても他を続行し、選択した全 config が結果に
  残ること、集約が失敗になること
- **列挙コマンドの 2 契約** — パス列挙が行指向の出力と機械可読出力の双方で得られること、
  全件指定のテキスト出力は重複除去と並び替えを行う一方、機械可読出力は config ごとに分離して
  config をまたいだ重複除去をしないこと
- **絞り込みで 0 件になる実行** — 対象が 0 件でも形の変わらない文書が出ること

隔離した一時 HOME の下で動き、fixture flake は nput を局所パスの入力として参照し、依存を
lock の pin へ追従させてオフラインで評価する。シナリオの途中で flake を書き換えて故障を
注入し、復元する。
