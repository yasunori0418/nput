# RISK-a1622cdd: 巻き戻し中の 1 件の失敗が残りの巻き戻しを道連れにし、復旧できない項目も報告されない

## リスク

undo ジャーナルの巻き戻しで個々の逆操作が失敗したとき、そこで巻き戻し全体が中断する。
本来は best-effort で残りを巻き戻し切ってから、元のエラーと巻き戻せなかった項目の一覧を
まとめて stderr へ報告して停止する契約である（→ REQ-9fca28c9）。

失敗する経路が現実にあるのがこのリスクの前提になる。逆操作の対象パスは、前方操作の
あとに別のプロセス・別のツールによって動かされうるし、巻き戻しを引き起こしたのと同じ
permission 障害が逆操作側にも効くことがある。中断すると、まだ巻き戻せたはずの項目が
FS に残り、RISK-68e810c5 と同じ「部分適用の痕跡」を別経路で作る。

報告側の欠落も同じ重さで扱う。巻き戻せなかった項目が沈黙すると、ユーザーは「巻き戻しは
全部成功した」と読んで手当てしないまま次の apply へ進む。この報告は失敗経路であり、
成功時沈黙の対象外として常時 stderr へ出す必要がある。journal が空のとき（FS 書き込みの
前に失敗した場合）に「N 件復旧できず」という虚偽の行を出すのも、同じ信頼性の毀損として
本リスクに含む。

## 実現性

**likelihood: medium** — 巻き戻し自体の失敗は正常系では起きず、故障注入で初めて踏む経路。
そのぶん実装の回帰が通常のテストをすり抜けやすい。

**impact: high** — 巻き戻し不能項目の沈黙は、ユーザーが FS の破損に気付く手段を奪う。

## 緩和

TC-83fe0d4a のうち「best-effort 継続」と「全件報告（空 journal で虚偽の件数行を出さない
ことを含む）」の 2 条件が緩和する。同 TC の LIFO 順序と journal 破棄の条件は
RISK-68e810c5 側の担当。
