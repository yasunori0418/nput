# RISK-3de9753f: 評価スイート自身の盲点でアサートが空虚に緑になる

## リスク

検証手段を nix-unit（点の不変条件）と namaka（面のスナップショット）の 2 本立てにする設計
（DSG-fb49e36c）には、その組み合わせに固有の盲点が 2 つある。どちらも「スイートが緑なのに
守られていない」という形をとり、他のどのアサートの信頼性も同時に下げる。

**テスト名の後勝ち衝突**: nix-unit のスイートはテストディレクトリの列挙で組み立てられ、
`//` マージが衝突を後勝ちで黙って解決する。テスト名がファイル横断で衝突すると、落ちるはずの
アサートが実行されないまま緑になる。落ちないだけでなく、実行されていないこと自体が出力に
現れない。

**スナップショットへの委ね過ぎ**: namaka のスナップショットは変更時に丸ごと再承認される。
規範である性質をスナップショットだけに委ねると、「変わったこと」は差分として見えても
「変わってよかったのか」は問われないまま承認が通る。

**この破れが design に張る理由**: どちらも 2 手段併用という検証設計の選択に由来し、別の設計
（例: 生成した文書を Go 側の契約テストで直接検証する）へ置き換えれば消える。
`docs/agents/sara-graph.md` の判別規約に従い design 側へ張る。

## 評価

- likelihood: medium — テスト名の衝突は leaf ファイルを追加するたびに起こりうる。
  スナップショットの再承認は文書構造を変えるたびに判断を求められる
- impact: high — 空虚に緑になったアサートは、それが守っていたはずの不変条件を丸ごと無防備に
  する。しかも失敗ではなく成功として現れるため、気づく契機が無い
- level: high

## 対処

スナップショットへの委ね過ぎは TC-de6514e2 が緩和する（同 TC が、規範である性質は名前付き
アサート側で守りスナップショットへ委ねない旨を条件として持つ）。

**テスト名の後勝ち衝突は残余リスクで、テストによる緩和手段を持たない**。一意性は
TP-36e90d5d が定めるスイート組み立ての規約であり、現状その遵守はレビューでのみ担保される。
慣行としては各 leaf ファイルがファイル固有の接頭辞（`testEscapesBase*` / `testAnchorName*` /
`testResolveMarker*` / `testFarmEntries*` など）を付けて衝突を避けており、`escapes-base.nix` の
ヘッダコメントはその意図を明記している。ただしこれは規約の遵守方法であって機械検出ではない。
衝突を機械検出する手立て（アグリゲータ側でのマージ前重複検査など）は本 item の対象外で、
必要になった時点で別途起こす。

同種の「テスト自身の検出力の限界」は他にもある。CASE-879a93da の `expectedError.msg` は部分
一致でゲートの取り違えを検出できず、TC-1d69350e の組み立て検証は `lib/manifest.nix` の生成式を
複製した独立コードなので本体の変更に追随しない。いずれも本 risk と同じ「緑なのに守られていない」
形で、緩和手段を持たない残余である。

## 出典

`tests/nix-unit.nix` のアグリゲータ実装（`lib.foldl' (acc: m: acc // m)` の後勝ちマージ）と
`tests/namaka/` の運用からの逆算（→ Issue #273「L1〜L4」節）。2 手段併用の設計判断は
DSG-fb49e36c、その規約は TP-36e90d5d が持つ。
