# RISK-e659f9dd: 空親ディレクトリの剪定が行き過ぎ、または残骸を残す

target を除去した後、空になった親ディレクトリのチェーンを root 境界まで剪定する。この歩行は
両方向に失敗しうる。止まるべきところで止まらなければ、ユーザーのディレクトリ（root 自体・
symlink である祖先・nput 管理外の空 dir）まで消す。逆に剪定を怠れば、apply のたびに空
ディレクトリの残骸が積もる。

「空である」の判定も脅威の一部になる。foreign な実ファイルが 1 つでも残っているディレクトリを
空と誤判定すれば、そのファイルごと消えるか、rmdir が失敗して除去全体が止まる。剪定は本質的に
best-effort であり、失敗したときにエラーで apply 全体を落とすのではなく警告に留めることも
この脅威への対処にあたる。

## 想定する失敗

- root 境界を越えて剪定し、root 自体やその外側を消す
- 祖先が symlink のときにその先へ踏み込んで剪定する
- 非空（foreign ファイルを含む）ディレクトリを空と誤判定する
- 多階層の空チェーンを 1 階層しか剪定せず残骸が積もる
- 剪定失敗が致命エラーになり、成功した除去まで巻き添えで失敗扱いになる

## 張り先の判断

requirement へ張る。「空の親を root 境界まで保守的に剪定する」はユーザーが FS 上で直接
観測する振る舞いであり、剪定の実装手段を差し替えても懸念は残る。
